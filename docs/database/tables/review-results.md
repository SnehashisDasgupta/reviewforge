# Review Results Table Design

## Purpose

The `review_results` table stores the overall output generated by the AI for a review request.

It summarizes the findings, metrics, recommendations, and quality score produced after processing the repository.

---

# Responsibilities

- Store AI-generated review summary
- Store quality metrics
- Link review issues
- Preserve review history

---

# Relationships

| Related Table | Relationship |
|---------------|--------------|
| reviews | Many Results → One Review |
| review_issues | One Result → Many Issues |

---

# Columns

| Column | Type | Nullable | Description |
|---------|------|----------|-------------|
| id | UUID | ❌ | Primary key |
| review_id | UUID | ❌ | Parent review |
| overall_score | DECIMAL(5,2) | ❌ | Repository quality score |
| summary | TEXT | ❌ | AI-generated summary |
| strengths | TEXT | ✅ | Positive observations |
| weaknesses | TEXT | ✅ | Areas for improvement |
| recommendations | TEXT | ✅ | Suggested improvements |
| created_at | TIMESTAMP WITH TIME ZONE | ❌ | Creation timestamp |

---

# Constraints

```text
PRIMARY KEY(id)

FOREIGN KEY(review_id)
REFERENCES reviews(id)
```

---

# Indexes

- idx_review_results_review

---

# Business Rules

- Every review has one result.
- Results become immutable after generation.
- Scores range from 0–100.
